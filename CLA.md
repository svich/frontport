## Accepting this Agreement

This section describes how acceptance works on GitHub. It is not part of the
Agreement's terms.

Frontport uses a GitHub Action,
[CLA Assistant Lite](https://github.com/step-security/contributor-assistant-github-action),
to collect acceptances:

1. Read this Agreement.
2. Open your pull request. If you haven't accepted this version of the
   Agreement, the CLA bot comments on the pull request and its CLA check
   fails.
3. From the GitHub account that authored the commits, post a comment on the
   pull request containing exactly this line:

   ```text
   I have read the Frontport Individual Contributor License Agreement version 1.0 and I accept it
   ```

4. The bot records your acceptance and the CLA check passes. If the check
   doesn't update, comment `recheck`.

The bot records your GitHub username, GitHub user ID, the comment and the
pull request number in a public file on the repository's `cla-signatures`
branch. After a pull request is merged, the bot locks its conversation so
acceptance comments can't be edited or deleted.

You only need to accept once per Agreement version. If the Agreement changes,
you'll be asked to accept the new version on your next pull request. Each
co-author of a pull request must accept separately. If you can't accept by
pull request comment, contact the Project Owner at
<a.svidchenkov@gmail.com> to accept another way.

**What doesn't count as acceptance.** Opening a pull request, ticking a
checkbox in a pull request template, or adding a `Signed-off-by` line under
the [Developer Certificate of Origin](https://developercertificate.org/) is
not treated as acceptance of this Agreement. A DCO sign-off certifies where
code came from; it does not grant the licenses in this Agreement.

**Legal status.** The bot only collects and records acceptances; it does not
by itself make them legally binding. Whether comment-based acceptance is
enforceable in a particular jurisdiction has not been confirmed by legal
review.

## Contributing for an employer or organization

If you write code as part of your job, or your employment contract gives your
employer rights to what you create, your employer may own your contribution.
Before submitting:

- **Check your employment agreement** and any policy on open-source
  contributions.
- **Get written permission** from someone at your employer who has authority
  to give it, or a written waiver of your employer's rights in the
  contribution. Keep it; you don't need to send it unless asked.
- **If the organization itself is contributing**, or prefers to sign on its
  own behalf, it needs a separate corporate contributor license agreement.
  The project doesn't publish one yet; contact the Project Owner at
  <a.svidchenkov@gmail.com>.

If you're unsure whether your employer has rights in your contribution, ask
before submitting.
